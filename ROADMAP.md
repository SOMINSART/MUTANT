# MUTANT public roadmap

> The roadmap tracks evidence, not promises. A milestone is complete only when the linked artifact exists in this repository.

## Current position

**Phase 0 — Public foundation.** The repository has a public identity, an authentication design note, a launch visual, and a press kit. It does not yet contain an executable product.

## Phase 0 — Define the mutation

- [ ] Publish one sentence answering: **what does MUTANT transform, for whom, and why is that change valuable?**
- [ ] Name the primary user and the painful problem.
- [ ] Choose an initial license.
- [ ] Define one measurable success criterion for the first prototype.
- [ ] Add repository description, topics, and social preview in GitHub settings.
- [ ] Record the first architecture decision.

**Exit evidence:** a concise product brief committed to `docs/product/brief.md`.

## Phase 1 — First living prototype

- [ ] Commit the smallest end-to-end implementation of the core transformation.
- [ ] Add a reproducible local quickstart.
- [ ] Add one automated happy-path test and one failure-path test.
- [ ] Connect the authentication design to real code, or explicitly declare that authentication is not required.
- [ ] Document data inputs, outputs, persistence, and deletion.

**Exit evidence:** a stranger can clone the repository and reproduce the central result.

## Phase 2 — Prove usefulness

- [ ] Publish a short, unedited demonstration.
- [ ] Recruit 3–5 external testers and record anonymized feedback.
- [ ] Document what changed because of that feedback.
- [ ] Add security, privacy, and failure-mode tests proportional to the product.
- [ ] Publish tagged release `v0.1.0` with a changelog.

**Exit evidence:** independent users can describe the value in their own words.

## Phase 3 — Public launch

- [ ] Update the press kit with verified features, screenshots, demo, license, and release link.
- [ ] Publish a technical article explaining one non-obvious design decision.
- [ ] Prepare honest launch posts for relevant communities.
- [ ] Contact a small, relevant list of writers with a personalized factual pitch.
- [ ] Track coverage and corrections in the press kit.

**Exit evidence:** every public claim links to code, a test, a release, a demo, or independent feedback.

## Visibility loop

```text
Build one verifiable improvement
        ↓
Document the decision and evidence
        ↓
Publish a small release or progress note
        ↓
Invite specific feedback
        ↓
Credit useful contributors
        ↓
Repeat
```

## What MUTANT will not do

- Pretend proposals are implemented features.
- Announce production readiness without tests and deployment evidence.
- Call itself open source before a license is selected.
- Manufacture testimonials, stars, coverage, or community activity.
- Publish private credentials, personal data, or unredacted security material.

## Résumé français

MUTANT est actuellement en **phase de fondation publique**. La priorité n’est pas d’accumuler des promesses, mais de publier une définition précise, un premier prototype reproductible, des preuves d’utilité et enfin une version étiquetée. Chaque étape doit laisser une preuve vérifiable dans le dépôt.
