# Contributing to MUTANT

Thank you for helping MUTANT evolve in public. The project is at an early foundation stage, so clear evidence and focused proposals are more valuable than large speculative changes.

## Before contributing

1. Read the [README](README.md) and [roadmap](ROADMAP.md).
2. Search existing issues before opening a new one.
3. For a substantial feature or architecture change, open an issue first.
4. Never include credentials, private data, generated secrets, or third-party material without permission.

## Good first contributions

- Clarify an ambiguous statement without inventing product facts.
- Improve accessibility, translations, examples, or diagrams.
- Add a reproducible test for behavior that already exists.
- Turn a roadmap item into a small, reviewable proposal.
- Report a broken link, contradiction, or unverifiable claim.

## Proposal format

Please describe:

- **Problem:** who experiences it and what evidence exists?
- **Smallest useful change:** what is the narrowest solution?
- **Verification:** how will another person prove it works?
- **Risks:** security, privacy, cost, compatibility, and maintenance.
- **Alternatives:** what simpler option was considered?

## Pull requests

- Keep each pull request focused on one outcome.
- Link the relevant issue.
- Explain user-visible behavior and trade-offs.
- Add or update tests when behavior changes.
- Update documentation in the same pull request.
- Do not label proposed behavior as shipped.
- Use conventional, readable commit messages such as `docs:`, `feat:`, `fix:`, `test:`, or `security:`.

## Review standard

A change is ready when:

- its purpose is understandable without private context;
- claims are backed by code, tests, or cited evidence;
- failure behavior is documented;
- no secret or personal data is exposed;
- a stranger can reproduce the result.

## Communication

Be direct, curious, and respectful. Critique ideas and evidence, not people. Harassment, threats, doxxing, discrimination, or deliberate disruption are not accepted.

## Security reports

Do not open a public issue for a vulnerability. Follow [SECURITY.md](SECURITY.md).

## Attribution

Meaningful contributions should be credited in the pull request, changelog, or release notes. MUTANT does not buy or fabricate community activity.
